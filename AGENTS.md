# Agent notes

Humans: the user guide is **https://idodavis.github.io/paradox-modding-tools/** (source `docs/`). Do not treat this file as the manual.

## Learned User Preferences

- Prefer the smallest clear implementation: cut duplication, dead-end helpers, and over-engineering; do not add code for backwards compatibility.
- Never hand-edit `frontend/bindings/**`; regenerate with `task common:generate:bindings` after Go DTO/service changes.
- Put display fields (relative paths, origin) on Go payloads. `session.Locate` already returns origin+rel; use `filepath.Rel` for vanilla/install paths. Do not write frontend path-stripping helpers.
- Render inspector/table fields from the payload. Do not re-derive view-models for values Go already computed.
- Prefer stdlib (`filepath.Rel`, Node `node:path`) over custom utilities when client-side path math is unavoidable.
- Change only what was explicitly requested; avoid unrelated refactors or drive-by edits.
- Keep plans short, actionable, and free of stale wording after iterative edits; ask clarifying questions when requirements are ambiguous.
- Prefer game-agnostic shared parser/semantics logic; keep game-specific facts and outputs under each game's own files/dirs.
- Prefer a JSON semantic model when it can hold the needed baseline structure; avoid SQLite unless relationships or volume truly require it.
- Put performance-sensitive work in Go behind the Wails 3 bridge when that stays maintainable; keep UI logic in the frontend otherwise.
- Prefer "patch" (not "update"/"campaign") for mod version retargeting, and prefer clear product names over ambiguous jargon.
- Prefer Nuxt UI component patterns (`:items` and similar) over ad-hoc `v-if`/`v-model` control flow where Nuxt UI fits.
- Prefer denser layouts where editor/diff/merge content dominates the viewport and path/config chrome stays compact.
- When cleaning code, keep useful comments and user-facing behavior; reduce complexity without expanding scope.
- Do not re-wrap, pack, or densify code to move a line-count gate. A reduction counts only when a representation, pass, helper, or file is deleted. `wc` is a consequence metric, never a reason to change formatting.

## Learned Workspace Facts

- Workspace IDE embeds monaco-vscode-api workbench (Monaco + VS Code services); product chrome stays Nuxt. UTF-16 exists only at `languageClient.ts` (Monaco). Everywhere else is UTF-8 byte offsets.
- **Scan is three walks over every file, nothing retained between them.** `lang/index` parses each file into a flat pre-order `Fact` array and walks it three times: pass 1 emits definitions and the ten grammar rows that need no global knowledge (top-level keys, `namespace`/event ids, keyword names, the script-name table, `$PARAM$`, `prefix:id` cites, wrappers) and keeps only a block skeleton per file; the nested join marks databases on a bootstrap tree; pass 2 re-parses and folds every value into the schema tree; pass 3 re-parses and resolves references and edges against the settled tree. Parsing is a small share of the scan, so the extra passes are cheap and the per-file records they replaced (occurrence lists, tallies, node chains) are gone.
- **Thin language engine:** no `go:embed` of game knowledge. Game-specific extract overrides live only in `game/registry.go`; the shared Jomini grammar is in `parser/jomini`, which never imports `game`. Wrong or missing `formatVersion` discards the file (no migrations).
- **The type system is read, not inferred.** Each game ships its own in `script_docs`: `event_scopes.log` (scope-type universe), `event_targets.log` (`Input Scopes` → `Output Scopes`, and `Global Link`+`Requires Data` = the citable `prefix:key` table), `effects.log` / `triggers.log` (`Supported Scopes` = input type, `Supported Targets` = argument type), `on_actions.log` (`Expected Scope`). `catalog/schema.go` parses all three syntaxes (CK3 `----` blocks, EU5/Vic3 markdown headings, bare `name:` blocks) into one `Schema` on the cache. Do not re-derive any of this by voting. A link name may be declared twice — once global, once contextual — so link entries **merge**; output types are verified never to disagree.
- **Binding types to databases:** `catalog.bindKinds` joins declared types to harvested folders by set membership over `prefix:id` citations, yielding `PrefixKinds` and `KindScope` (kind → scope type). A type may span folders (CK3 decisions across DLC dirs), so `KindBinding.Kinds` is a list; `Owners()` drops folders under `bindShare` because some folders are *keyed by* another type's ids (CK3 coats of arms are keyed by title). Binding runs twice — once on top-level defs, then again after `applyDerivedDefs` harvests nested databases (CK3 faiths under religions).
- **The learned schema is one tree.** `index.Tree` holds one `Node` per position under each kind's root: what every value written there resolved to (the intersection of kinds, with `loc` among them), whether the block holds names, whether its keys are rows of a database (`Rows`/`Def`, from the nested join or from a definition-body field whose every value names a sibling block, as a game rule's `default` does), and its block class (structure, database, body with trigger/effect/modifier bits, list). Structures unify by key across positions (`Structs`), `Known` is every key the install writes or declares, `Binds` tie declared prefixes to databases. One classifier (`KeyClass`) and one table (`classes`) say what a key is and what it folds to; `Schema.Step` is the one descent the scan and the editor share. Nothing is voted and there are no floors; the reporting policy in `learned-schema.md` §5 is the only judgment.
- **Deleted with the type system, with the measurement that justified it:** `VoteEngineTokens` elected every `$PARAM$` substitution site as an effect, turning CK3's 1,905 real effects into 10,337 completion entries (82% noise like `$CHARACTER$.culture`); effects/triggers now come only from `Schema`. `VotePrefixKinds` missed every prefix that matters (`culture` `title` `trait` `character` `province`) while inventing 13 non-prefixes (`ai=modifiers`, `event_id=namespace`); the prefix table now comes only from declared links. `VoteCallKinds` elected `subtract`, `trigger_localization`, `namespace` and the GUI value `right|top` as invocable kinds; a call is now simply a `scripted_*` macro (`game.IsMacroKind`). **Without script_docs there is no engine API and no prefix table** — that is deliberate, because a half-wrong table is worse than none, and the archive means a user runs `script_docs` once per game version.
- **script_docs archive:** `catalog/schemaarchive.go` copies the recognized dump files into `cache/script-docs-{installId}-{version}/` on every scan (1–2.2 MB per game). `LoadSchema` prefers live dumps and refreshes the archive; the archive stands in when the user's are gone. `Schema.Source` is `live` / `archive` / `missing` for the UI. Raw files are archived (not just the parsed `Schema`) so a `CacheFormatVersion` bump can re-derive without the user relaunching the game. `DropVanillaFiles` removes the archive too. PMT **cannot** generate dumps itself: `script_docs` is console-only, with no CLI flag and no autoexec hook.
- **Ownership / import DAG (one-way):** `parser/jomini` (leaf CST) ← `parser/loc` (Decode only). `game` is a leaf (titles, MatchExtract, FIOS, KeyIdentity, ParsePrefixed, ScriptName/IsEphemeral). `catalog` imports jomini, loc, game — persist VanillaCache + loc sidecar; harvest mods into RAM (`BuildIndex` → `Harvest`). `session` is the only type that holds VanillaCache + harvest maps. `lsp` and `views` are siblings (never import each other); they use the session query API and must not persist. `release` is a leaf (Workshop extras, upload-temp copy/ignore, Markdown↔BBCode); `ReleaseService` delegates to it. Parent `parser/` is a folder, not a Go package. There is no `lang/` package, no `parser/gui`, no GraphIndex, no persisted mod Index, no public `Cache()` getter.
- **Persist vs RAM:** the install `Index` is the cache file byte for byte (`vanilla-{installId}-{version}.json`, `CacheFormatVersion` in `index.go`; a mismatch means rescan), with the data-row tier (`vanilla-data-…`) loaded lazily on a miss. A cache keeps only the references the editor cannot re-derive from the open file: localization references and macro calls; everything else is re-derived per file. The workspace is a second `Index` of the same type built over the install's by the same three passes (`BuildWorkspace`), learning tree nodes only where the install is silent, and re-run per edited file by `IndexFile`. Two workspaces on the same Steam install share one install index, which is why the two stay separate objects. `latest` is a legal cache-key version. App config is JSON (`config.json`, `FormatVersion` 1); a version mismatch means empty and writable, any other read failure means empty and read-only so a transient failure never overwrites the real file. `script_docs` is the authority for the engine API.
- **Who uses which store:** Scan writes VanillaCache + loc sidecar, never a mod index. `BuildIndex` returns `Harvest` for session maps (mods). session queries both internally. lsp/views never concatenate cache+harvest slices. Settings health uses VanillaCache `scannedAt`/version plus live `DefCount`.
- **Helper rule:** a helper lives with the data it reads. `TokenAt`/`Decode`/`BlockForKey` in jomini; `Winner`/`IsFIOS` in catalog+game; `MatchExtract`/`CanonicalKind`/`KeyIdentity`/`ParsePrefixed`/`ParseTyped`/`ScriptName` in game; `DisplayRel`/`Locate`/`KindFor` in session; `# pmt:ignore` / `subjectAt` in lsp; neighborhood BFS + inspector pretty-script in views; Workshop upload-temp/ignore and MD↔BBCode in `release`.
- **Test layout (enforced by hand, not by a test):** every `X_test.go` sits beside an `X.go` in the same package (`X_windows_test.go` pairs with `X.go`). The only other names allowed are `gate_*_test.go` (cross-cutting ship gates over a real install), `bench_*_test.go` (budgets and benchmarks), `probe_*_test.go` (`-tags probe` measurements), and `<pkg>_test.go` (shared fixtures). A test is named for what it tests, not for where it was written; move code to meet a test before splitting the test.
- **JSON app store:** `services.OpenStore()` / `store.go`. Types: `GameInstall` (`VersionDetected`, `IsBroken`), `Workspace` (`DefaultLocLang`, `HideExplorerBinaries`), settings map. No SQLite, no DbService.
- **Wails registered services:** Settings, File, Workspace, Session (owns Pool, EnsureSession, `RebuildInstallSemantics`, health), Ide (`*SessionService` + lsp; Monaco Did*/Hover/…), Views (`*SessionService` + views; graph, `GetHealth`, `LookupLoc`), Wiki, Search, Release. No DbService, no LogService, no Merge/Patcher, no `GetDependencies`, no `GetCompatibility`/`GetLocCoverage`, no one Wails service per Vue page. Removed Wails RPCs: `SetActiveWorkspace`, `Drop` (`Pool.Drop` is internal; EnsureSession drops other live sessions). Workspace switch is Pinia localStorage `workspace.activeId` + `EnsureSession`. `GetIdeRoots` lives on WorkspaceService. After Go DTO/service changes: `task common:generate:bindings`. Never hand-edit `frontend/bindings/**`. Frontend aliases: `@services` → `frontend/bindings/paradox-modding-tools/services`; catalog/views models from `@services/internal/catalog/models` and `@services/internal/views/models`; Session/Ide/Views from `@services/{sessionservice,ideservice,viewsservice}`.
- **Session API:** `Session` holds `Install` and `Work` (`*index.Index`), the mods in load order, the default language and the editor buffers, under one `sync.RWMutex`. Callers read the two indexes as fields (posting lists, `Loc`, `Schema`, `Docs`, `Declared`); the session's own methods are the buffer overlay (DidOpen/Change/Close/Save, FileText, Parsed), the writers (ReplaceCache, MergeVanillaLoc, SetDefaultLang, StartWatch, Close), the questions that read both halves (Defs/Resolve/ResolveOfKind/VanillaDefs/RefsTo/Edges/LocSite/DefaultLoc/LocKeys/Node/Params/ValuesOf/Contests/FindDefsOf/Macros) and the path questions only the mod list can answer (Locate/KindFor/DisplayRel/OriginName/CalendarFor). The lock is held per request: `withSession` in `services` takes RLock once and lsp/views run inside it lock-free; the writers take `Lock` and must not be called under a read lock. Prose lookups (field docs, token usage, declared types) live in `lsp/docs.go`.
- **Pool:** `EnsureSession` Drops every other live session (one live workspace). `Pool.Drop` is not a Wails RPC. DeleteGameInstall refuses while in use (does not Drop).
- Workspaces: first-launch/retriggerable wizard, dropdown switching, user-specified mod paths, multiple installs per game, broken-path marking, default loc language, install version pin/`latest`, DeleteGameInstall (refuses while in use), DeleteWorkspace (the workspace record only — mod folders on disk stay).
- Scan hot-swap: `RebuildInstallSemantics(installId)` ReplaceCache/ReplaceVanillaLoc on every live session on that install, emit `lang:cache-updated`; languageClient re-Diagnoses open LANGS docs (no app reload).
- Event-graph layout is frontend `dagre` layered + Vue Flow nested `parentNode` (origin groups). Go returns nodes/edges with no coordinates. Via-effect edges stay. Vue templates the payload (no regroup of gates/effects/locRows).
- **Frontend husk:** appearance + interaction only. `SEEDS` in `frontend/src/ide/colorThemes.ts` is the only palette; `applySeedCss` injects onto `:root`. Families: pmt, ck3, eu5, vic3, catppuccin, one, github, horizon. `themes.css` is the structural `@theme` / `--ui-*` bridge. Syntax tokens from `@codingame/monaco-vscode-theme-defaults-default-extension` (dark_plus / light_plus); all `@codingame/monaco-vscode-*` packages pin the same version via npm overrides. Table filters live in UTable column state; fetch state in Pinia Colada `useQuery`/`useMutation`. No path-stripping helpers; payloads carry `rel`/`origin`/`originName`. Kept as presentation: dagre (`useGraphLayout`) and Vue Flow origin parents.
- Monaco language providers use `registerLanguageClient(() => workspaceId)` — no `useWorkspaceStore()` inside provider callbacks.
- Tool pages use `useLiveEnabled` / `useWorkspaceStore().ensureReady()` — success means a **live** session (`LanguageHealth.indexReady` from `EnsureSession`), not merely `defCount > 0`.
- On Windows, the parser is pure Go (`CGO_ENABLED=0`). Linux stays `CGO_ENABLED=1` for Wails WebKit. `go test -race ./services/internal/parser/...` should work on Windows.
- **Measure sprawl** (repo root, bash): `find services -name '*.go' ! -name '*_test.go' | xargs wc -l | tail -1`, same for `*_test.go`, and `find frontend/src -name '*.vue' -o -name '*.ts' -o -name '*.css' | xargs wc -l | tail -1`. Success of a de-sprawl pass is fewer files and lines, not extra layers.
