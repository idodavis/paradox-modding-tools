# Agent notes

Humans: the user guide is **https://idodavis.github.io/paradox-modding-tools/** (source `docs/`); the backend's map is [services/README.md](services/README.md). Do not treat this file as the manual.

## Learned User Preferences

- Prefer the smallest clear implementation: cut duplication, dead-end helpers, and over-engineering; do not add code for backwards compatibility.
- Never hand-edit `frontend/bindings/**`; regenerate with `task common:generate:bindings` after Go DTO/service changes.
- Put display fields (relative paths, origin) on Go payloads. `Session.Where` already gives origin and rel; use `filepath.Rel` for vanilla/install paths. Do not write frontend path-stripping helpers.
- Render inspector/table fields from the payload. Do not re-derive view-models for values Go already computed.
- Prefer stdlib (`filepath.Rel`, Node `node:path`) over custom utilities when client-side path math is unavoidable.
- Change only what was explicitly requested; avoid unrelated refactors or drive-by edits.
- Keep plans short, actionable, and free of stale wording after iterative edits; ask clarifying questions when requirements are ambiguous.
- Prefer game-agnostic shared parser/semantics logic; keep game-specific facts and outputs under each game's own files/dirs.
- Prefer a JSON semantic model when it can hold the needed baseline structure; avoid SQLite unless relationships or volume truly require it.
- Put performance-sensitive work in Go behind the Wails 3 bridge when that stays maintainable; keep UI logic in the frontend otherwise.
- Prefer "patch" (not "update"/"campaign") for mod version retargeting, and prefer clear product names over ambiguous jargon.
- Prefer Nuxt UI component patterns (`:items` and similar) over ad-hoc `v-if`/`v-model` control flow where Nuxt UI fits.
- Prefer denser layouts where editor/diff/merge content dominates the viewport and path/config chrome stays compact.
- When cleaning code, keep useful comments and user-facing behavior; reduce complexity without expanding scope.
- Do not re-wrap, pack, or densify code to move a line-count gate. A reduction counts only when a representation, pass, helper, or file is deleted. `wc` is a consequence metric, never a reason to change formatting.

## Product / stack

- Terminology: [GLOSSARY.md](GLOSSARY.md). Measured per-game syntax facts, with reproductions: [GAME-SYNTAX.md](GAME-SYNTAX.md) — read it before changing the schema stage or the entry detector.
- Paradox Modding Tools is a Wails **v3.0.0-beta.21** desktop app (Go **1.27.1** backend, Vue 3 + Nuxt UI + Pinia + Colada frontend) for Paradox modders, licensed under GPL-3.0-or-later.
- **Supported OS:** Windows and Linux (traditional desktop distros, GTK4 + WebKitGTK 6). **macOS is not supported** — do not add Mac downloads, Mac user docs, or a macOS issue-template option. Leave the Wails `darwin` Taskfile in the tree; do not advertise it.
- Product is workspace-centric: Library, IDE, Event Graph, **Workspace Health** (FIOS/LIOS + depends/dangling + loc coverage), Patch Center (wiki notes **only**), Publish (Steam + Paradox Mods copy). CK3, Vic3, EU5 (partial). No Compare, Merge, Inventory, or Patcher/Impact services.
- GUI preview is a future feature; `.gui` is the same Jomini CST as `.txt`, not a third parser.
- Releases: per-platform **zips** on GitHub (`paradox-modding-tools-{windows-amd64,linux-amd64}.zip` + sibling `SHA256SUMS`; Windows on ARM runs the amd64 zip under emulation). In-app updater is `github.New` (`ChecksumAsset: "SHA256SUMS"`) — do not set `Prerelease: true`. Workshop publish runs in a second copy of the app itself (`steam-publish`), which loads the game's own copy of Steam's library where `GameInfo.SteamLibrary` says the install keeps it; PMT ships nothing of Steam's.
- Local develop/build: Taskfile (`task dev`, `task build`) with `wails3` v3.0.0-beta.21. Windows `CGO_ENABLED=0`. Linux `CGO_ENABLED=1` (WebKit). `task test:race` (`go test -short -race ./...`) works on Windows.

## Learned Workspace Facts

- **The language engine** is `services/internal/lang/*` with `session` and `lsp` over it; the app builds and runs on it. Read `services/internal/lang/README.md` (what it must do, the pipeline, the package map) before touching it; each package's README holds its design, and `.claude/plans/engine.md` holds the owner's decisions (D-n).
- Workspace IDE embeds monaco-vscode-api workbench (Monaco + VS Code services); product chrome stays Nuxt. The editor client is a framework-free core, `frontend/src/ide/editorCore.ts` (payload → display: the hover card's markdown, ranges), and one adapter, `ide/languageClient.ts`, that registers it with the workbench. UTF-16 exists only in `editorCore.ts`'s conversion; everywhere else is UTF-8 byte offsets.
- The workbench boots from `WorkspaceToolBar.vue` on whichever workspace page opens first (its `ide-boot` query: the folders mount, then `EnsureSession`), behind the page. Nothing may call a Monaco API before that, since an early call starts Monaco with services the workbench cannot replace; read-only code outside the editor is drawn by Pierre (`lib/code.ts`), not Monaco.
- **Thin language engine:** the only embedded game data is `lang/shipped`'s backup schemas (what the dumps declare, never dumps or vanilla words), used when a dump file is missing. The language rules and each game's file layout live only in `game/lang-rules.go`, each game's identity and install facts in `game/game.go` (`game/README.md`); the shared Jomini syntax is in `lang/jomini`, which never imports `game`. No file PMT writes carries a format version: the app is unreleased, so a changed struct means Rebuild or Reset data, never a migration.
- **Ownership / import DAG (one-way):** `lang/jomini` (leaf CST) ← `lang/loc`, `lang/source` ← `lang/schema` ← `lang/shipped` ← `lang/index` ← `session` ← `lsp`. `lang` is the engine and nothing under it imports `session`, `lsp` or `steam`. `lang/source` knows every file of an install, a mod or a dump folder (the roots that mirror the game layout, the inventory, each file's format, an image's header) and interprets none of it. `lang/schema` is the schema stage: one position tree that the dumps, the install's docs, the wiki and vanilla's evidence write into in trust order (`Build`), the entry detector (`Entries`, the one place that says what an entry is, for both stages), and `Speaks`, the one rule for when a claim may accuse; it imports `game` (the registry's rows), `wiki` (the page text), `lang/jomini` and `lang/source`, and parses only what it is handed. `lang/shipped` embeds the backup schemas (the dump part only) and holds the generator that writes them; it imports `lang/schema` and `local` (the stored form). `lang/index` is the index stage: the walk (`Walk`), which turns a file into records by the schema's walker (`schema.Read`, the one reader of script) and the name rules; the definitions, references and localization entries it records, for an install and for a workspace's mods; resolution at query time in the game's load order (`Resolve`, `Lookup`, `Winner`, the folders a mod's `replace_path` unloads); and the scan with the install's cache (`Scan`, `SaveInstall`, `LoadInstall`). It infers nothing: every database, every position and every rule about a written word comes from the schema. It imports `game`, `wiki`, `lang/shipped` and `local` (the cache folder, the atomic `Write`, the stored form, a mod's descriptor). `session` is one workspace open in the editor: the install's index and schema, the mods' index built over it, the files the editor has open, and the lookups over all of them (load order, localization, where a path sits). One RWMutex: readers hold RLock for a whole request; the writers (`Did*`, `Changed`) lock themselves and are never called under a read lock. `lsp` answers the editor's requests from one walk of the open file (`index.Walk`), stopped at the cursor or run whole; its payloads carry display data and the frontend templates the text. It never persists. `game` is a leaf (the language rules and each game's layout in `lang-rules.go`; titles, the registry, install detection, where each game keeps Steam's library in `game.go`). `local` is this machine's files: the app's folders, the one atomic `Write` every save goes through, the stored form of a cache or shipped file (`Encode`, `Decode`: gob inside gzip), and a mod's own Paradox files (descriptor, thumbnail, the new-mod skeleton); it imports `game`. `steam` is everything the Steam Workshop reads: the publish (a second run of this executable, `ServeSteamPublish`), the ISteamUGC binding, Markdown↔BBCode, the description files, the Workshop extras, `.workshop-ignore` and the upload copy (walked with `lang/source.Walk`); it imports `local`, `game` and `lang/source`. `wiki` imports `game` and `local`. `EventGraphService` and `HealthService` answer a page's question from the same index: the event graph and one event's detail from the references that fire events and on_actions (`session.Fires`, `session.FiredBy`), and the workspace's health from the names two origins define, dangling references, untranslated localization and the editor's own findings. The services root holds Wails services only.
- **Test layout (enforced by hand, not by a test):** each package has one test file, `<pkg>_test.go`, and a gate over a real install lives in it behind its environment variable, which `task test:gate` turns on together. The sweep (`TestSweep` in `services_test.go`) runs only behind `PMT_TEST_SWEEP` (`task test:sweep`). A test is named for what it tests.
- **App config** is JSON (`config.json`, no format version); a missing file is a first run, any other read failure means empty and read-only so a transient failure never overwrites the real file.
- **JSON app config:** `services.OpenApp()` / `appservice.go`, the App service (the app-wide RPCs: settings, version, updates, reset; it holds `config.json` for every other service through `read`/`mutate`). Types: `GameInstall` (`VersionDetected`), `Workspace` (`DefaultLocLang`, `HideExplorerBinaries`; each mod's `IsBroken` is derived from disk), settings map. No SQLite, no DbService.
- **Wails registered services:** Log (`pmt.log`, the frontend's log lines, crash detection), App, File, Workspace, Wiki, Search, Release, Session (the live sessions, EnsureSession, the health strip; every scan starts by itself and tells its stages on `lang:scan-progress`, with no Rescan and no unread count), Ide (Monaco Did*/Hover/…), EventGraph (`GetEventGraph`, `GetEventDetail`, `SearchRoots`) and Health (`GetHealth`, `LookupLoc`). No DbService, no Merge/Patcher, no `GetDependencies`, no `GetCompatibility`/`GetLocCoverage`, no one Wails service per Vue page. Removed Wails RPCs: `SetActiveWorkspace`, `Drop` (dropping a session is internal; EnsureSession drops other live sessions). Workspace switch is Pinia localStorage `workspace.activeId` + `EnsureSession`. `GetIdeRoots` lives on WorkspaceService. Every bound field has a camelCase JSON tag. After Go DTO/service changes: `task common:generate:bindings`. Never hand-edit `frontend/bindings/**`. Frontend aliases: `@services` → `frontend/bindings/paradox-modding-tools/services`; the payload models from `@services/models`, `@services/internal/lsp/models` and `@services/internal/{session,game,wiki}/models`; the services from `@services/{sessionservice,ideservice,eventgraphservice,healthservice,appservice}`.
- **Events** Go sends the frontend (`emit` in `sessionservice.go`): `lang:ready` (a session is built; its workspace id), `lang:failed` (it could not be built; the same id), `lang:scan-progress` (`{installId, percent, stage}`), `lang:cache-updated`, `lang:calendar-changed`, `fs:changed` (`{path, deleted}`, from the session's file watcher; `ide/fsBridge.ts` tells the workbench), `wiki:updated` (`{gameId, error}`).
- **Live sessions:** `EnsureSession` drops every other live session (one live workspace); dropping is not a Wails RPC. DeleteGameInstall refuses while in use (does not drop).
- Workspaces: first-launch/retriggerable wizard, dropdown switching, user-specified mod paths, multiple installs per game, a mod folder that is missing marked broken, default loc language, the install's version read at each scan, DeleteGameInstall (refuses while in use), DeleteWorkspace (the workspace record only — mod folders on disk stay).
- **Event Graph** (`pages/EventGraphPage.vue`, `components/eventGraph/`, `composables/useEventGraph.ts`): Go returns nodes and edges with no coordinates; `useEventGraph` lays them out left to right with `dagre` and Vue Flow draws them. The graph draws events, on_actions and the definitions that fire them; a scripted effect between two is its edges' label (`Edge.Via`: the chain of scripted effects entered), or a node of its own when the page's "Show scripted effects and triggers" is on. The detail's Fires and Fired by follow the same rule (`session.Fires`, `session.FiredBy`). Vue templates the payload.
- **Workspace Health** (`pages/HealthPage.vue`, `components/health/HealthTable.vue`, `components/health/HealthDetail.vue`, `composables/useHealth.ts`): cards (conflicts, overrides, dependencies — depends on or affected by, from comparing a winning definition's statement with the one it hides — dangling references, loc gaps, and one per kind of finding the editor's checks make) pick the table; each column head sorts and, where its values are few, filters; a row opens its sites in the pane.
- **Frontend husk:** appearance + interaction only. `SEEDS` in `frontend/src/ide/colorThemes.ts` is the only palette; `applySeedCss` injects onto `:root`. Families: pmt, ck3, eu5, vic3, catppuccin, one, github, horizon. `themes.css` is the structural `@theme` / `--ui-*` bridge. Syntax tokens from `@codingame/monaco-vscode-theme-defaults-default-extension` (dark_plus / light_plus); all `@codingame/monaco-vscode-*` packages pin the same version via npm overrides. Table filters live in UTable column state; fetch state in Pinia Colada `useQuery`/`useMutation`. No path-stripping helpers; payloads carry `rel`/`origin`, and the workspace store names an origin (`originName`).
- Monaco language providers come from `registerLanguageClient(getWorkspaceId, origin)` in `ide/languageClient.ts`; the adapter imports no store, and `ide/workbenchHost.ts` hands it the origin lookup.
- Tool pages use `useLiveEnabled` / `useWorkspaceStore().ensureReady()` — success means a **live** session (`LanguageHealth.ready` from `EnsureSession`), not merely `defs > 0`.
- On Windows, the Jomini parser (`lang/jomini`) is pure Go (`CGO_ENABLED=0`). Linux stays `CGO_ENABLED=1` for Wails WebKit. `task test:race` works on Windows.
- **Measure sprawl** (repo root, bash): `find services -name '*.go' ! -name '*_test.go' | xargs wc -l | tail -1`, same for `*_test.go`, and `find frontend/src -name '*.vue' -o -name '*.ts' -o -name '*.css' | xargs wc -l | tail -1`. Success of a de-sprawl pass is fewer files and lines, not extra layers.
