# Agent notes

Humans: the user guide is **https://idodavis.github.io/paradox-modding-tools/** (source `docs/`). Do not treat this file as the manual.

## Learned User Preferences

- Prefer the smallest clear implementation: cut duplication, dead-end helpers, and over-engineering; do not add code for backwards compatibility.
- Never hand-edit `frontend/bindings/**`; regenerate with `task common:generate:bindings` after Go DTO/service changes.
- Put display fields (relative paths, origin) on Go payloads. `session.Locate` already returns origin+rel; use `filepath.Rel` for vanilla/install paths. Do not write frontend path-stripping helpers.
- Render inspector/table fields from the payload. Do not re-derive view-models for values Go already computed.
- Prefer stdlib (`filepath.Rel`, Node `node:path`) over custom utilities when client-side path math is unavoidable.
- Change only what was explicitly requested; avoid unrelated refactors or drive-by edits.
- Keep plans short, actionable, and free of stale wording after iterative edits; ask clarifying questions when requirements are ambiguous.
- Prefer game-agnostic shared parser/semantics logic; keep game-specific facts and outputs under each game's own files/dirs.
- Prefer a JSON semantic model when it can hold the needed baseline structure; avoid SQLite unless relationships or volume truly require it.
- Put performance-sensitive work in Go behind the Wails 3 bridge when that stays maintainable; keep UI logic in the frontend otherwise.
- Prefer "patch" (not "update"/"campaign") for mod version retargeting, and prefer clear product names over ambiguous jargon.
- Prefer Nuxt UI component patterns (`:items` and similar) over ad-hoc `v-if`/`v-model` control flow where Nuxt UI fits.
- Prefer denser layouts where editor/diff/merge content dominates the viewport and path/config chrome stays compact.
- When cleaning code, keep useful comments and user-facing behavior; reduce complexity without expanding scope.
- Do not re-wrap, pack, or densify code to move a line-count gate. A reduction counts only when a representation, pass, helper, or file is deleted. `wc` is a consequence metric, never a reason to change formatting.

## Product / stack

- Terminology: [GLOSSARY.md](GLOSSARY.md). Measured per-game syntax facts, with reproductions: [GAME-SYNTAX.md](GAME-SYNTAX.md) — read it before changing any inference pass.
- Paradox Modding Tools is a Wails **v3.0.0-beta.16** desktop app (Go **1.26.5** backend, Vue 3 + Nuxt UI + Pinia + Colada frontend) for Paradox modders, licensed under GPL-3.0-or-later.
- **Supported OS:** Windows and Linux (traditional desktop distros, GTK4 + WebKitGTK 6). **macOS is not supported** — do not add Mac downloads, Mac user docs, or a macOS issue-template option. Leave the Wails `darwin` Taskfile in the tree; do not advertise it.
- Product is workspace-centric: Library, IDE, Event Graph, **Workspace Health** (FIOS/LIOS + depends/dangling + loc coverage), Patch Center (wiki notes **only**), Publish (Steam + Paradox Mods copy). CK3, Vic3, EU5 (partial). No Compare, Merge, Inventory, or Patcher/Impact services.
- GUI preview is a future **views** feature; `.gui` is the same Jomini CST as `.txt`, not a third parser.
- Releases: per-platform **zips** on GitHub (`paradox-modding-tools-{windows-amd64,linux-amd64}.zip` + sibling `SHA256SUMS`; Windows on ARM runs the amd64 zip under emulation). In-app updater is `github.New` (`ChecksumAsset: "SHA256SUMS"`) — do not set `Prerelease: true`. Workshop publish runs in a second copy of the app itself (`steam-publish`), which loads the game's own copy of Steam's library where `GameInfo.SteamLibrary` says the install keeps it; PMT ships nothing of Steam's.
- Local develop/build: Taskfile (`task dev`, `task build`) with `wails3@v3.0.0-beta.16`. Windows `CGO_ENABLED=0`. Linux `CGO_ENABLED=1` (WebKit). `go test -race ./services/internal/parser/...` should work on Windows.

## Learned Workspace Facts

- **The language engine is being rebuilt.** Phase 1 of `.claude/plans/language-engine.md` deleted the old one: `lang/declared`, `lang/index`, `lang/session/session.go`, `lang/lsp`, `views`, `game/catalog.go`, and the Session, Ide and Views services; Phases 2 to 7a have rebuilt all of it, up to `views` and the Session, Ide and Views services, so `task test` and CI cover the whole `services` tree again. The app itself does not build until Phase 7b rewrites the frontend against the new payloads. The bullets that described the old engine were removed with it, and each phase adds back what it builds. The plan's §5.0 holds the terms, its §11 the packages, and `.claude/plans/language-engine/` the work orders, the old engine's behaviour rows (`rows.md`), its hand tables (`tables.md`) and what its code knew (`carryover.md`).
- Workspace IDE embeds monaco-vscode-api workbench (Monaco + VS Code services); product chrome stays Nuxt. UTF-16 exists only at `languageClient.ts` (Monaco). Everywhere else is UTF-8 byte offsets.
- **Thin language engine:** no `go:embed` of game knowledge. Per-game facts live only in `game/game.go`; the shared Jomini syntax is in `lang/jomini`, which never imports `game`. No file PMT writes carries a format version: the app is unreleased, so a changed struct means Rebuild or Reset data, never a migration.
- **Ownership / import DAG (one-way), as the tree stands during the rebuild:** `lang/jomini` (leaf CST) ← `lang/loc`, `lang/source` ← `lang/schema` ← `lang/learn` ← `lang/index` ← `session` ← `lsp`. `lang` is the engine and nothing under it imports `session`, `lsp`, `local` or `steam`. `lang/source` knows every file of an install or a mod (the roots that mirror the game layout, the inventory, each file's format, an image's header) and interprets none of it. `lang/schema` holds what the game declares (the vocabulary read from the script_docs dumps, the game info read from the install's prose), the schema a scan learns with its text file, the one hand table of name tokens, and `schema.Reader`, the only place that decides what a written word is; it imports `lang/jomini`, `lang/loc` and `lang/source`, never `game`, and parses no game file itself. `lang/learn` is the one place that infers: it reads an install's files once and gives the schema, deciding by a fact the game declares (a token's usage, a link's output, an info file's type), then by a row of the registry, then by once, most or every, and never by a tuned number; it imports `lang/jomini`, `lang/loc`, `lang/schema` and `lang/source`, never `game`, so its caller hands it the registry's rows. `lang/index` is what a scan found and where: the file inventory, and the definitions, references, edges and localization entries written in the files, for an install and for a workspace's mods; load order (`Winner`, `Contests`, the folders a mod's `replace_path` unloads); and what the install's cache holds (`Body`, whose lookups `Restore` rebuilds and which are never stored). It infers nothing: every kind, every field and every rule about a written word comes from the schema and `schema.Reader`. It also imports `game`, for what each entry-mode word means and for the registry's rows it hands the learner. `session` is one workspace open in the editor: the install's index and schema, the mods' index built over it, the files the editor has open, and the lookups over all of them (load order, localization, where a path sits). One RWMutex: readers hold RLock for a whole request; the writers (`Did*`, `Changed`, `Replace`) lock themselves and are never called under a read lock. `lsp` answers the editor's requests from one descent to the cursor (`index.Probe`, the harvest's own walk) and one reading by `schema.Reader`; its payloads carry `schema.Value` and the frontend templates the text. It never persists. `game` is a leaf (titles, the registry, install detection, where each game keeps Steam's library). `local` is this machine's files: the app's folders, the one atomic `Write` every save goes through, the install cache (`SaveInstall`, `LoadInstall`, `ScannedAt`, `DropInstall`), and a mod's own Paradox files (descriptor, thumbnail, the new-mod skeleton); it imports `lang/index`, `lang/schema` and `game`. `steam` is everything the Steam Workshop reads: the publish (a second run of this executable, `ServeSteamPublish`), the ISteamUGC binding, Markdown↔BBCode, the description files, the Workshop extras, `.workshop-ignore` and the upload copy (walked with `lang/source.Walk`); it imports `local`, `game` and `lang/source`. `wiki` imports `game` and `local`. `EventGraphService` and `HealthService` answer a page's question from the same index: the event graph and one event's detail from the edges the harvest wrote, and the workspace's health from contests, dangling references, localization coverage and file coverage. The services root holds Wails services only.
- **Test layout (enforced by hand, not by a test):** each package has one test file, `<pkg>_test.go`, and a gate over a real install lives in it behind its environment variable, which `task test:gate` turns on together. The one exception is `services/sweep_test.go`, whose `sweep` build tag keeps it out of every other run. A test is named for what it tests.
- **App config** is JSON (`config.json`, no format version); a missing file is a first run, any other read failure means empty and read-only so a transient failure never overwrites the real file.
- **JSON app config:** `services.OpenConfig()` / `configservice.go`, the Config service (the config, its settings RPCs, version, updates, reset). Types: `GameInstall` (`VersionDetected`, `IsBroken`), `Workspace` (`DefaultLocLang`, `HideExplorerBinaries`), settings map. No SQLite, no DbService.
- **Wails registered services:** Config, File, Workspace, Wiki, Search, Release, Session (the live sessions, EnsureSession, `RebuildInstallSemantics`, the scan queue, the health strip), Ide (Monaco Did*/Hover/…), EventGraph (`GetEventGraph`, `GetEventDetail`) and Health (`GetHealth`, `LookupLoc`). No DbService, no LogService, no Merge/Patcher, no `GetDependencies`, no `GetCompatibility`/`GetLocCoverage`, no one Wails service per Vue page. Removed Wails RPCs: `SetActiveWorkspace`, `Drop` (dropping a session is internal; EnsureSession drops other live sessions). Workspace switch is Pinia localStorage `workspace.activeId` + `EnsureSession`. `GetIdeRoots` lives on WorkspaceService. After Go DTO/service changes: `task common:generate:bindings`. Never hand-edit `frontend/bindings/**`. Frontend aliases: `@services` → `frontend/bindings/paradox-modding-tools/services`; the payload models from `@services/models`, `@services/internal/lsp/models` and `@services/internal/lang/{schema,index}/models`; the services from `@services/{sessionservice,ideservice,eventgraphservice,healthservice,configservice}`.
- **Live sessions:** `EnsureSession` drops every other live session (one live workspace); dropping is not a Wails RPC. DeleteGameInstall refuses while in use (does not drop).
- Workspaces: first-launch/retriggerable wizard, dropdown switching, user-specified mod paths, multiple installs per game, broken-path marking, default loc language, install version pin/`latest`, DeleteGameInstall (refuses while in use), DeleteWorkspace (the workspace record only — mod folders on disk stay).
- Event-graph layout is frontend `dagre` layered + Vue Flow nested `parentNode` (origin groups). Go returns nodes/edges with no coordinates. Via-effect edges stay. Vue templates the payload (no regroup of gates/effects/locRows).
- **Frontend husk:** appearance + interaction only. `SEEDS` in `frontend/src/ide/colorThemes.ts` is the only palette; `applySeedCss` injects onto `:root`. Families: pmt, ck3, eu5, vic3, catppuccin, one, github, horizon. `themes.css` is the structural `@theme` / `--ui-*` bridge. Syntax tokens from `@codingame/monaco-vscode-theme-defaults-default-extension` (dark_plus / light_plus); all `@codingame/monaco-vscode-*` packages pin the same version via npm overrides. Table filters live in UTable column state; fetch state in Pinia Colada `useQuery`/`useMutation`. No path-stripping helpers; payloads carry `rel`/`origin`/`originName`. Kept as presentation: dagre (`useGraphLayout`) and Vue Flow origin parents.
- Monaco language providers use `registerLanguageClient(() => workspaceId)` — no `useWorkspaceStore()` inside provider callbacks.
- Tool pages use `useLiveEnabled` / `useWorkspaceStore().ensureReady()` — success means a **live** session (`LanguageHealth.indexReady` from `EnsureSession`), not merely `defCount > 0`.
- On Windows, the parser is pure Go (`CGO_ENABLED=0`). Linux stays `CGO_ENABLED=1` for Wails WebKit. `go test -race ./services/internal/parser/...` should work on Windows.
- **Measure sprawl** (repo root, bash): `find services -name '*.go' ! -name '*_test.go' | xargs wc -l | tail -1`, same for `*_test.go`, and `find frontend/src -name '*.vue' -o -name '*.ts' -o -name '*.css' | xargs wc -l | tail -1`. Success of a de-sprawl pass is fewer files and lines, not extra layers.
